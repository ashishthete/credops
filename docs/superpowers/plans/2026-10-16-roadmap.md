when the previous phase is merged. That way each plan builds on the code as it

## Contracts Phase 1 fixes for every later phase

- **Data:** each phase adds a numbered migration to `src/main/db/migrations.ts`.
  Earlier migrations are never edited.
- **IPC:** each phase adds channels to `IpcContract` in `src/shared/ipc.ts` and
  handlers in `src/main/ipc/handlers/<area>.ts`. The renderer only ever calls
  `window.opsdeck.invoke(channel, ...args)`.
- **Audit:** every meaningful action calls `audit.append({...})` from the main
  process. Actions are dot-namespaced (`vault.unlock`, `tunnel.start`,
  `release.start`). Each phase extends the `AuditAction` union.
- **Deploy runs:** deployments emit an append-only `run_event` stream with
  UUIDv7 ids, behind the `DeployRunner` interface. The UI reads only the stream,
  so phase 10 can swap in `HubRunner`.
- **Secrets:** anything that leaves the process (audit details, logs, Teams, AI
  prompts) passes through `redact()` from `src/main/security/redact.ts`.
