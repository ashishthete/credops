# OpsDeck Services Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Replaces the Phase 8b plan** (`2026-10-19-phase8-deployments-8b.md`). Build
it on `phase8-deployments`, on top of 8a. The 8b file stays in the repo only
as history; nothing in it is built separately. Where this plan reuses an 8b
interface (the pipeline reducer, the log buffer, the Phase 9 mounts), it
restates the interface here.

**Goal:** Give every environment named services (`service` or `db`), make
"pick services, run one playbook for exactly those" the way OpsDeck deploys,
and add live compose logs, db tunnels and copy-to-environment around them.
Also export and import the whole config as JSON, without secrets (Addendum: config import/export,
controller's call).

**Architecture:**
- **Main.** A new `ServiceStore` (`src/main/deploy/service-store.ts`) owns
  the `services` table, which replaces `apps`. A Phase 8 Deployment becomes
  the **checkout** that services point at.
  - A pure `resolveSelection` (`src/main/deploy/selection.ts`) turns
    `serviceIds` into affected checkouts, each marked whole or partial.
  - `ReleaseService` plans from that selection. The pure generator takes a
    per-checkout service list.
  - One compose helper (`src/main/deploy/compose.ts`) builds every
    `docker compose` command: deploy, rollback and logs.
- **Logs and tunnels reuse earlier phases.** Logs are a compose variant of
  Phase 7's `ContainerService.follow`. Db tunnels are ordinary Phase 5
  tunnels, which `ServiceTunnels` (`src/main/deploy/service-tunnel.ts`)
  manages.
- **Renderer.**
  - The Environment view gets a Services section.
  - The release experience (store, pipeline reducer, picker wizard, pipeline
    view, live log, history, map) is built around service selection from
    the start.

**Tech Stack:**
- Electron main, with better-sqlite3 (JSON1 is available) and ssh2 through
  the existing pools;
- React 19, react-router and framer-motion in the renderer, with lucide
  icons;
- vitest, with jsdom for the renderer.

**Spec:** `docs/superpowers/specs/2026-10-19-services-design.md`, which
extends `2026-10-16-opsdeck-design.md`. Read it before the 8a plan
`2026-10-19-phase8-deployments.md`, whose Global Constraints still hold.

## Global Constraints

**Rules from the controller, verbatim:**
- Real ansible-playbook, docker or SSH never run in tests. Tests use fakes, a tmp HOME and 127.0.0.1 on port 0.
- Generated playbook and shell text is asserted at parse level only.
- No secrets in plaintext on disk, logs, audit or IPC.
- Audit records store hostCount and serviceCount, never host ids or labels.
- Protected environments need typed-name confirmation.
- known_hosts is read-only; nothing writes to ~/.ssh.
- No new dependencies; no `pnpm add`/`install`.
- Animations are fast: springs 600/38, exits 90 ms, staggers capped at 150 ms (see `src/renderer/src/ui/motion.ts`).
- Test command: `./node_modules/.bin/vitest run`. Typecheck: the repo's tsc scripts (check package.json).

**Typecheck commands** (package.json `typecheck`):
- `./node_modules/.bin/tsc --noEmit -p tsconfig.node.json`
- `./node_modules/.bin/tsc --noEmit -p tsconfig.web.json`

There is no eslint. If anything rewrites `pnpm-workspace.yaml`, run
`git checkout pnpm-workspace.yaml`.

**Baseline** at c5c263a: 105 test files and 1671 tests pass.

**Inherited from 8a, unchanged:**

  `no_log`), are wiped with `drop()`, and all text passes through `redact`.

**Copy:**

**Motion:**

- rollback: `rb_checkout, rb_env, rb_build, rb_up, rb_tag`;
- step ids are `<runId>:<kind>`.

## Review Focus

These failure modes are listed most likely first. Each is pinned by a test in
the task that owns the code.

1. **A service changes between preflight and Start.** For example, the user
   deletes `esg`, moves it to another checkout or renames its compose
   service while the wizard is open. Start must refuse with
   `<name> changed since preflight; run preflight again`. It must never
   deploy the stale list.
   - *Pinned:* Task 6, `start refuses when a selected service changed since preflight`.
2. **A compose service or project that looks like an option or carries shell
   syntax**, such as `--rm`, `-p`, `a b` or `x;rm`. It is refused when saved,
   and the generator and the logs command refuse it again even if it reaches
   them from the database.
   - *Pinned:* Task 2, `compose service must match COMPOSE_SERVICE`.
   - *Pinned:* Task 4, `composeArgs refuses option-like and shell tokens`.
3. **Rolling back a release after a later release deployed a sibling
   service.** Example: R1 deployed `esg` and R2 then deployed `js_foundry`
   from the same checkout. Rolling back R1 is allowed, because R1 is still
   the latest release for `esg`. The plan rebuilds only `esg`. The confirm
   says the checkout's code moves back for `js_foundry` too.
   - *Pinned:* Task 6, `rollback of R1 is allowed after R2 touched only a sibling, and rebuilds esg only`.
   - *Pinned:* Task 11, `rollback confirm names siblings whose code moves back`.
4. **A db tunnel whose local port is busy, or whose via-host is unreachable.**
   The row shows Phase 5's real state (`failed` with Phase 5's message) and
   never `up`. The address appears only once the runtime is `up`.
   - *Pinned:* Task 7, `open reports the Phase 5 failure and never claims up`.
   - *Pinned:* Task 8, `db row shows the address only when up`.
5. **A db service whose via-host was deleted or left the environment.**
   Open falls back to the default app host. With no app host it fails with
   `Pick a via-host for <name>; this environment has no app host`.
   - *Pinned:* Task 7, `via-host gone falls back to the default app host, else asks for one`.

      environment_id TEXT NOT NULL REFERENCES environments(id) ON DELETE CASCADE,
      name TEXT NOT NULL, kind TEXT NOT NULL CHECK (kind IN ('service','db')),
      position INTEGER NOT NULL DEFAULT 0, description TEXT NOT NULL DEFAULT '',
      deployment_id TEXT REFERENCES deployments(id) ON DELETE SET NULL,
      compose_service TEXT, url TEXT, url_check_from TEXT CHECK (url_check_from IN ('mac','host')),
      last_deployed_commit TEXT, last_release_id TEXT REFERENCES releases(id) ON DELETE SET NULL,
      db_engine TEXT CHECK (db_engine IN ('postgres','mysql','mongodb','redis','other')),
      db_address TEXT, db_port INTEGER CHECK (db_port BETWEEN 1 AND 65535),

  export const MAX_SERVICES = 512                      // replaces MAX_APPS
  export type ServiceKind = 'service' | 'db'
  export type DbEngine = 'postgres' | 'mysql' | 'mongodb' | 'redis' | 'other'
  export const DB_DEFAULT_PORT: Record<DbEngine, number | null> = { postgres: 5432, mysql: 3306, mongodb: 27017, redis: 6379, other: null }
  interface ServiceBase { id: string; environmentId: string; name: string; position: number; description: string; createdAt: string; updatedAt: string }
  export interface AppServiceMeta extends ServiceBase { kind: 'service'; deploymentId: string | null; composeService: string; url: string | null; urlCheckFrom: HealthFrom; lastDeployedCommit: string | null; lastReleaseId: string | null }
  export interface DbServiceMeta extends ServiceBase { kind: 'db'; dbEngine: DbEngine; dbAddress: string; dbPort: number; viaHostId: string | null; localPort: number | null; tunnelId: string | null }
  export type ServiceMeta = AppServiceMeta | DbServiceMeta
  export type ServiceInput =
    | { kind: 'service'; environmentId: string; name: string; description?: string; deploymentId: string | null; composeService?: string; url?: string | null; urlCheckFrom?: HealthFrom }
    | { kind: 'db'; environmentId: string; name: string; description?: string; dbEngine: DbEngine; dbAddress: string; dbPort?: number; viaHostId?: string | null; localPort?: number | null }

  export function listNames(names: string[]): string                       // "a", "a and b", "a, b and c"
  export function pickAppHost(hosts: { hostId: string; role: HostRole; label: string }[], checkoutHostIds: string[]): string | null
  export function deriveTag(tag: string, sourceEnv: string, targetEnv: string): string | null
  export function stripSecretRefs(template: string): string               // every ${secret:…} becomes ''

    `targetEnv.toLowerCase()`. It returns `null` when nothing matched or
    the result fails `GIT_REF`.

**Interfaces:**
- **Consumes:** `ConfigFile`, `parseConfigFile`, `CONFIG_MAX_BYTES` and
  `buildConfigExport` (Task 12).
- **Produces:**
  ```ts
  export type ImportAction = 'add' | 'update' | 'unchanged' | 'skip'
  export interface ImportItem { kind: keyof ConfigCounts; id: string; name: string; action: ImportAction; reason?: string; fields?: string[] /* changed field names on update */ }
  export interface ImportPreview { token: string; items: ImportItem[]; counts: Record<ImportAction, number>; needsSecret: { kind: keyof ConfigCounts; name: string; field: string }[]; protectedEnvironments: string[] /* names that would be updated */ }
  export interface ImportResult { counts: Record<ImportAction, number>; needsSecret: ImportPreview['needsSecret'] }
  export function planImport(db: Database, file: ConfigFile): Omit<ImportPreview, 'token'>
  export function applyImport(deps: { db: Database; audit: AuditLog; vault: { assertUnlocked(): void } }, file: ConfigFile, opts: { typedNames: string[]; expected: ImportPreview['counts'] }): ImportResult
  ```
- **IPC:**
  - `'config:importOpen': { args: []; result: ImportPreview | { errors: string[] } | null }`.
    Main opens the open dialog with a JSON filter. A cancel returns `null`.
    - Main checks the size with `stat`: more than `CONFIG_MAX_BYTES` is
      refused with `The file is larger than 5 MB`, before anything is read.
    - Then main reads the file, runs `parseConfigFile` and `planImport`,
      and keeps the parsed file in memory under a random `token`. At most
      one token is held, and it expires after 10 minutes (builder's call).
  - `'config:importApply': { args: [token: string, opts: { typedNames: string[] }]; result: ImportResult }`.
  - `'config:importDiscard': { args: [token: string]; result: void }`.
  - The renderer never sends a path or file contents.
- **Matching.** An object matches by `id` first. Failing that, it matches
  by name within its parent:

  | Kind | Name match |
  |---|---|
  | product | `name` |
  | identity | `label` within its vault |
  | host | `label` |
  | environment | `name` |
  | tunnel | `label` within its host |
  | checkout | `name` within its environment |
  | service | `name` within its environment |

  - A name match takes the local id. Every reference in the file to the
    file's id is remapped to that local id.
  - **Ambiguous matches.** Identities (label within the vault) and tunnels
    (label within the host) have no UNIQUE constraint. Several local
    candidates for one name give `skip` with the reason
    `ambiguous: <n> matches`.
  - An ssh-key `ItemRef` is matched by key label within the vault, which is
    also not unique. Several matches leave the reference unresolved, and it
    is listed under `needsSecret` with the same reason. Secrets are unique
    per vault, so their refs are never ambiguous.
  - **`update`** means some exported field differs, and `fields` lists the
    names. Equal fields give `unchanged`.
  - **Link rows** (`product_environments`, `environment_hosts`,
    `host_vaults` and `deployment_vaults`) are only ever added, or have
    their role updated. They are never removed.
  - **Nothing missing from the file is deleted or changed.**
- **Secret references.**
  - `ItemRef` and `VaultRef` resolve by vault name, then item name, in the
    local DB.
  - An unresolved reference leaves the field unset and adds a
    `needsSecret` entry:
    - a checkout's become secret becomes `null`;
    - an env template line `KEY=${secret:ref-N}` becomes `KEY=`;
    - an unresolved vault link is not added.
  - **When a field can't be left unset:**
    - a new identity with `auth: 'key'` and no resolvable key, or with
      `auth: 'password'`, is `skip` with the reason
      `needs a secret: <field>`. The password is never in the file, so a
      new password identity is always skipped. Hosts and environments that
      reference a skipped identity import with `identityId` null, and they
      are listed in `needsSecret`;
    - an **existing** identity keeps its local key and password.
- **Apply.**
  - It calls `vault.assertUnlocked()`, then works inside one
    `inTransaction`, in this order:
    1. identities, products and hosts (jump hosts are inserted with `null`,
       then set);
    2. environments and links;
    3. tunnels, checkouts and services.
  - It recomputes `planImport` inside the transaction. If those counts
    differ from `expected`, it throws
    `The config changed since the preview; open the file again`.
  - Each row goes through the same validation the stores use. Any error
    rolls the whole import back.
  - **Protected environments.** Every environment named in
    `protectedEnvironments` must appear in `typedNames`. Otherwise apply
    throws `DeployError('CONFIRM_REQUIRED', 'Type <env> to update this protected environment')`.
    An environment being added needs no typed name.
  - Running tunnels are not restarted. A changed route applies on the next
    start (builder's call).
  - **Audit.** One `config.import` row is written after commit, with
    `details: { counts, needsSecret: needsSecret.length }`. It carries no
    ids, labels or path, and the per-row audits are not written.
  - Then `onChanged` fires for inventory, deploy and tunnels.
- **`ImportConfigDialog({ preview, onClose })`:**
  - It shows grouped counts (`Add n`, `Update n`, `Unchanged n`,
    `Skip n`) and expandable lists. Each list shows names and, for
    updates, the changed field names.
  - It shows a `Needs a secret` list.
  - Under it: `Nothing is deleted. Objects that are not in the file stay as they are.`
  - When `protectedEnvironments` is non-empty, there is one typed field
    per name, each labelled `Type <env> to confirm`. **Import** stays
    disabled until each field matches.
  - Errors from `importOpen` are listed with the heading
    `This file can't be imported`.
  - Closing without importing calls `config:importDiscard`.
  - The result toasts `Imported: <a> added, <u> updated`. When anything
    needs a secret, it adds `; <k> need a secret`.

**2. Gap rulings**

These are the builder's calls from spec §11, plus the gaps found while
planning:
- **Deps detection:** preflight `compose config --format json` plus
  `compose ps --status running`, parsed in main. The result is a warning,
  never a block.
- **Logs:** the Phase 7 `LogsDrawer` with tails 100/200/1000/5000, default
  200.
- **Local port:** a free port is picked and saved on first open.
- **Route changes:** a stopped tunnel is updated at once; for a running one
  the user is asked, and a decline leaves a stale-route note.
- **Copy conflicts:** skip and list, with no rename.
- **Membership:** added silently, with a toast.
- **Picker selection:** not remembered.
- **Whole checkout with no services:** selected through
  `PreflightRequest.checkoutIds`.
- **`deployment_runs.whole_checkout` column:** added, so rollback can use the
  release's form.
- **Logs privilege:** follows the checkout's `useSudo`, because Phase 7 has
  no per-host docker setting. The spec copy (§8.2, §12.7) is updated to
  match.
- **`deploy.*` audit:** the host label is dropped.
- **`last_deployed_commit`:** recorded per succeeded run, even when a later
  run fails with auto-rollback off.
- **Commit range:** the merge-base of the selected services' last commits.
- **Map:** db attachments only on a host whose address matches.
- **Motion tokens:** only `motion.ts` is copied from `cb452ff` (Task 8 Step 0), with no cherry-pick.
- **Config import/export (builder's calls inside the controller's addendum):**
  - snippets are left out, because the script is sealed;
  - `current_version` and last deployed commits are left out as release
    state;
  - export needs the vault unlocked;
  - the preview token is held in main for at most 10 minutes;
  - a new password identity is always skipped as needing a secret;
  - running tunnels are not restarted by an import;
  - ambiguous name matches are skipped with `ambiguous: <n> matches`.
